## 一、整体架构与表清单

涉及 6 张表（前 3 张是核心，后 3 张仅在到账登记勾选了关联流水 / 上传了附件时才会写入）：

| 表名 | 实体类 | 作用 |
|---|---|---|
| `FMS_RECEIVE_CREDIT_LETTER` | `FmsReceiveCreditLetterEntity` | 应收信用证主表（信用证台账） |
| `FMS_RCL_PRESENT_REGISTER` | `FmsRclPresentRegisterEntity` | 应收信用证交单登记表（主表，一次交单一行） |
| `FMS_RCL_PRESENT_REGISTER_CHILD` | `FmsRclPresentRegisterChildEntity` | 应收到账/应付结算登记表（子表，每次到账一行，`data_type=1` 表示应收） |
| `FMS_REGISTER_TRANS_ASSOCIA` | `FmsRegisterTransAssociaEntity` | 信用证结算交易关联表（到账登记时关联的资金流水） |
| `FMS_TRANSACTION_DETAILS_LABLE` | `FmsTransactionDetailsLableEntity` | 交易明细业务标签表（标识流水被该业务占用） |
| `FMS_ATTACHMENT` | `FmsAttachmentEntity` | 附件表（按 `bus_type` 区分交单附件 / 到账附件） |

代码层级关系：

```
FmsRclPresentRegisterController              (入口)
    └── FmsRclPresentRegisterService          (主流程：save / addAccount)
            ├── FmsReceiveCreditLetterService (主信用证状态推进)
            ├── FmsRclPresentRegisterChildService (子表：到账明细 / 流水关联)
            │       ├── FmsRegisterTransAssociaService     (流水关联释放)
            │       └── FmsTransactionDetailsLableService  (流水标签释放)
            └── FmsAttachmentService          (附件增删)
```

## 二、信用证状态机

`FmsConstants.letterStatus`：

| 编码 | 枚举 | 含义 |
|---|---|---|
| `0` | LETTER_0 | 签约 |
| `1` | LETTER_1 | 结清 |
| `2` | LETTER_2 | 签收 |
| `3` | LETTER_3 | 到账 |
| `4` | LETTER_4 | 新开 |
| `5` | LETTER_5 | 入库 |
| `6` | LETTER_6 | 出库 |
| `7` | LETTER_7 | 押汇 |
| `8` | LETTER_8 | 核销 |
| `9` | LETTER_9 | 废弃 |

本次两个接口涉及的状态推进路径：

```
[主信用证]   原状态  ──交单登记──►  6 出库  ──到账登记(beOver=0)──►  3 到账
[交单登记]   (无)    ──交单登记──►  6 出库  ──到账登记(beOver=0)──►  3 到账
```

### 3.1 接口入口


### 3.2 核心逻辑

`FmsRclPresentRegisterService.save`（281–306 行）：

1. `doValiData` 校验单据号唯一 + 交单金额不超开证金额；
2. DTO 转 Entity，强制 `status = 6`（出库）；
3. `fmsRclPresentRegisterDao.save(entity)` 新增交单主表；
4. 查询主信用证 `FmsReceiveCreditLetterEntity`，**强制把主表 status 也改成 6**；
5. 保存附件（`bus_type=RCL_PRESENT`）。

## 四、第二步：到账登记（PUT /fmsrclpresentregister/fmsrclaccountregister）

### 4.1 接口入口

`FmsRclPresentRegisterController.saveAccount` → `FmsRclPresentRegisterService.addAccount`

```java
@SysLog(value="保存",desc="应收信用证到账登记")
@PutMapping("fmsrclaccountregister")
public Result saveAccount(@RequestBody FmsRclPresentRegisterDTO fmsRclPresentRegister){
    fmsRclPresentRegisterService.addAccount(fmsRclPresentRegister);
    return Result.ok();
}
```

### 4.2 核心逻辑

`FmsRclPresentRegisterService.addAccount`（507–569 行）：

1. Redisson 分布式锁（key = `RECEIVE_REGISTER_` + 交单ID），防止并发重复登记；
2. 校验：到账明细不超过 100 条；本次到账金额累加 ≤ 交单金额；
3. `fmsRclPresentRegisterChildService.saveRegisterChild` 处理子表（到账明细 + 流水关联 + 流水标签）；
4. **关键判断**：若 `beOver = "0"`（`EnumType.YES_0`），则：
   - 交单主表 `status` 推进到 `3`（到账）；
   - 调用 `setLetterStatus` 推进主信用证状态到 `3`（条件：所有交单金额累加 = 开证金额 且全部到账）；
5. `updateAttachment` 先删后增到账附件（`bus_type=RCL_ACCOUNT`）；
6. `setData` 把到账字段回写到交单主表；
7. `setBeOver(dto.getBeOver())` 设置完结标志。

> 关键：示例 payload 中 `"beOver":"0"`，命中 `StrUtil.equals(dto.getBeOver(), EnumType.YES_0)`，**触发状态推进到 3（到账）**。

### 4.3 数据流转（按示例 payload）

#### ① `FMS_RCL_PRESENT_REGISTER_CHILD` 子表

本次 `registerList:[]` 为空 → 实际未 INSERT。若用户在前端填了到账明细，则写入以下字段：

| 字段 | 取值来源 |
|---|---|
| `ID` | uuid 自动生成 |
| `REGISTER_ID` | dto.id（交单登记 ID） |
| `RCL_ID` | dto.rclId |
| `DATA_TYPE` | `1`（应收） |
| `RECEIVE_AMOUNT` | 子表收款金额 |
| `CURRENCY_CODE` | 子表币种 |
| `RECEIVE_MODE` | 收款方式 |
| `RECEIVE_DATE` | 收款日期 |
| `PRESENT_BANK` / `RECEIVE_ACCOUNT` | 收款银行/账号 |
| `ACCOUNT_FEE` | 手续费 |
| `BOE_ABSTRACT` | 备注 |
| `LETTER_NUMBER` | 来自主信用证 |

> `saveRegisterChild` 默认 `enableDelete=true`，会先查出该 `registerId` 下原有 `dataType=1` 的子表，把前端没传回的旧记录**逻辑删除**。

#### ② `FMS_REGISTER_TRANS_ASSOCIA` / `FMS_TRANSACTION_DETAILS_LABLE`

仅当子表 DTO 的 `transAssociaList` 不为空（用户在到账登记时勾选了资金流水）才会写入。本次为空则不写。

#### ③ `FMS_RCL_PRESENT_REGISTER` 主表更新（`setData` + `setStatus` + `setBeOver`）

`setData` 方法（930–946 行）：

```java

    entity.setReceiveAccount(dto.getReceiveAccount());
    entity.setReceiveMode(dto.getReceiveMode());
    entity.setReceiveType(dto.getReceiveType());
    entity.setReceiveDate(dto.getReceiveDate());
    entity.setReceiveAmount(dto.getReceiveAmount());
    entity.setAccountFee(dto.getAccountFee());
    entity.setOperator(dto.getOperator());
    entity.setOperatorDate(dto.getOperatorDate());
    entity.setAccountRemark(dto.getAccountRemark());

```

| 字段 | 改动 |
|---|---|
| `STATUS` | **`6` → `3`（出库→到账）**（因为 beOver=0 命中） |
| `BE_OVER` | null → **`0`**（已完结=是） |
| `RECEIVE_ACCOUNT/MODE/TYPE/DATE/AMOUNT` | 按 dto 更新（本次为 null，等于把字段清空） |
| `ACCOUNT_FEE` | 按 dto 更新（本次为 null） |
| `OPERATOR/OPERATOR_DATE` | 按 dto 更新（本次为 null） |
| `ACCOUNT_REMARK` | 按 dto 更新（本次为 null） |
| `LAST_UPDATE_BY/DATE` | 当前用户/时间 |

> ⚠️ payload 把这些到账字段都置 null（前端没填到账明细），但 beOver=0 触发了状态推进 → 这是典型的"误操作"特征。

#### ④ `FMS_ATTACHMENT`

`updateAttachment` 先按 `busId + busType=RCL_ACCOUNT` 删除，再新增。本次 attachmentList 为空，等于**把到账附件全部清掉**。

#### ⑤ `FMS_RECEIVE_CREDIT_LETTER` 主信用证表

`setLetterStatus`（895–922 行）：当该信用证下**所有**交单金额累加等于开证金额，且其他交单也是"到账"或就是本次这条时，把主表 `STATUS` 从 `6` 改成 **`3`（到账）**。

## 五、误操作后逆向撤回 2 步的逻辑

撤回必须按"后进先出"顺序：**先撤到账登记（第 2 步）→ 再撤交单登记（第 1 步）**，且整个过程在一个事务里（`@Transactional(rollbackFor = Exception.class)`），否则一旦中途失败会导致状态不一致。

### 5.1 撤回顺序与数据回写矩阵

#### 步骤 A：撤销第 2 步「到账登记」

基于交单登记 ID = `fa40522b-7a5e-4474-b2ca-3ed852e0caa2`，逐项反向回写：

| 序号 | 表 | 操作 | 关键字段/条件 |
|---|---|---|---|
| A1 | `FMS_RCL_PRESENT_REGISTER_CHILD` | **逻辑删除**该交单下所有 dataType=1 的子表记录 | `WHERE register_id=? AND data_type='1'` → `enabled_flag='1', validity_flag='1'`。复用 `FmsRclPresentRegisterChildService.logicDeleteByRegister(registerId)` |
| A2 | `FMS_REGISTER_TRANS_ASSOCIA` | **释放关联流水** | `releaseRelationFlowByChildIdList(childIdList)`（按 A1 删前的 child.id 列表） |
| A3 | `FMS_TRANSACTION_DETAILS_LABLE` | **释放流水标签** | `releaseFlowLableListByBusDetailsId(childIdList)`（`busDetailsId` 即 child.id） |
| A4 | `FMS_RCL_PRESENT_REGISTER` | **回写交单主表**：① `STATUS` 由 `3` 回退为 `6`；② `BE_OVER` 由 `0` 回退为 null；③ 把 `setData` 写过的到账字段（`RECEIVE_ACCOUNT/MODE/TYPE/DATE/AMOUNT`、`ACCOUNT_FEE`、`OPERATOR/OPERATOR_DATE`、`ACCOUNT_REMARK`）置 null；④ `LAST_UPDATE_BY/DATE` 刷新 | `WHERE id = 'fa40522b-7a5e-4474-b2ca-3ed852e0caa2'` |
| A5 | `FMS_ATTACHMENT` | **到账附件不动**（撤回无需恢复被删附件，因为本次本来就是空）；若担心历史被 `updateAttachment` 误删，可在此步骤之前备份 `bus_type='RCL_ACCOUNT'` 的附件 | 可选 |
| A6 | `FMS_RECEIVE_CREDIT_LETTER` | **回退主信用证状态**：① `STATUS` 由 `3` 回退为 `6`；② 刷新 `LAST_UPDATE_BY/DATE` | `WHERE id = '55aa5f53-0c35-4a90-a272-cd8eef2ece02'`。注意：若该证下还有别的交单仍处于"到账"，不能简单回退，需重新计算（见【六、风险点】） |

#### 步骤 B：撤销第 1 步「交单登记」

| 序号 | 表 | 操作 | 关键字段/条件 |
|---|---|---|---|
| B1 | `FMS_ATTACHMENT` | **逻辑删除交单附件**（busType=RCL_PRESENT） | `deleteByBusIdAndType(registerId, 'RCL_PRESENT')`（本次附件为空，影响 0 行） |
| B2 | `FMS_RCL_PRESENT_REGISTER` | **逻辑删除交单主表** | 复用 `FmsRclPresentRegisterService.remove(new String[]{registerId})`，等价 SQL：`UPDATE ... SET enabled_flag='1', validity_flag='1', last_update_*=... WHERE id IN (?)` |
| B3 | `FMS_RECEIVE_CREDIT_LETTER` | **回退主信用证状态**：若该证下已无其他有效交单，把 `STATUS` 从 `6` 回退到上一步操作前的状态（通常是 `4` 新开 或 `2` 签收，需根据业务记录决定，**不能简单写死**）；刷新 `LAST_UPDATE_BY/DATE` | `WHERE id = '55aa5f53-0c35-4a90-a272-cd8eef2ece02'` |

> B3 注意：第一步 `save` 时把主表状态强制改成 `6`，但**没记录原状态**。建议：撤回前先查 `FMS_RECEIVE_CREDIT_LETTER`，如果当前是 `6`（出库）且本次要删的交单是该证下**唯一**有效交单，才把状态回退到一个安全值（如 `4` 新开）；否则保持不变。

### 5.2 撤回实现代码（建议新增到 `FmsRclPresentRegisterService`）

```java
/**
 * 逆向撤回：先撤到账登记，再撤交单登记.
 * @param registerId 交单登记ID（即误操作的交单 fa40522b-...）
 * @param originalLetterStatus 撤回后信用证主表应恢复的状态（由调用方根据业务判断传入，如 "4"）
 */
@SysLog(value="撤回",desc="应收信用证交单/到账登记撤回")
@Transactional(rollbackFor = Exception.class)
public void revokePresentAndAccount(String registerId, String originalLetterStatus) {
    // AI_GENERATE_START [revokePresentAndAccount]
    logger.info("revokePresentAndAccount start, registerId={}, originalLetterStatus={}",
            registerId, originalLetterStatus);

    FmsRclPresentRegisterEntity register = this.findOne(registerId);
    if (ObjectUtil.isEmpty(register)) {
        throw new ZteException("交单登记数据不存在");
    }
    String rclId = register.getRclId();

    // ===== 步骤A：撤销到账登记 =====
    // A1. 查出该交单下所有到账子表（dataType=1），先拿到 id 列表
    List<FmsRclPresentRegisterChildEntity> childList = fmsRclPresentRegisterChildService
            .queryRegisterCountByRid(registerId, FmsConstants.DATA_TYPE.RECEIVE.getCode());
    List<String> childIds = childList.stream()
            .map(FmsRclPresentRegisterChildEntity::getId).collect(Collectors.toList());

    // A2 + A3. 释放关联流水 + 流水标签（顺序：先释放标签和关联，再删子表）
    if (CollUtil.isNotEmpty(childIds)) {
        fmsTransactionDetailsLableService.releaseFlowLableListByBusDetailsId(childIds);
        fmsRegisterTransAssociaService.releaseRelationFlowByChildIdList(childIds);
    }
    // A1. 逻辑删除子表
    fmsRclPresentRegisterChildService.logicDeleteByRegister(registerId);

    // A4. 回写交单主表：状态回退到出库(6)、清空到账字段、beOver置空
    register.setStatus(FmsConstants.letterStatus.LETTER_6.getCode());
    register.setBeOver(null);
    register.setReceiveAccount(null);
    register.setReceiveMode(null);
    register.setReceiveType(null);
    register.setReceiveDate(null);
    register.setReceiveAmount(null);
    register.setAccountFee(null);
    register.setOperator(null);
    register.setOperatorDate(null);
    register.setAccountRemark(null);
    register.setLastUpdateBy(UserUtils.getUserId());
    register.setLastUpdateDate(new Date());
    fmsRclPresentRegisterDao.save(register);

    // A6. 回退主信用证状态：3 -> 6（如果当前是3才回退）
    FmsReceiveCreditLetterEntity letter = fmsReceiveCreditLetterService.findOne(rclId);
    if (ObjectUtil.isNotEmpty(letter)
            && FmsConstants.letterStatus.LETTER_3.getCode().equals(letter.getStatus())) {
        letter.setStatus(FmsConstants.letterStatus.LETTER_6.getCode());
        letter.setLastUpdateBy(UserUtils.getUserId());
        letter.setLastUpdateDate(new Date());
        fmsReceiveCreditLetterService.save(letter);
    }

    // ===== 步骤B：撤销交单登记 =====
    // B1. 删除交单附件
    fmsAttachmentService.deleteByBusIdAndType(registerId,
            FmsConstants.busType.RCL_PRESENT.getCode());
    // B2. 逻辑删除交单主表
    this.remove(new String[]{registerId});

    // B3. 回退信用证主表到原始状态（如该证下已无其他有效交单）
    List<FmsRclPresentRegisterEntity> remaining = this.findByParentId(rclId);
    if (CollUtil.isEmpty(remaining) && ObjectUtil.isNotEmpty(letter)
            && StrUtil.isNotBlank(originalLetterStatus)) {
        letter.setStatus(originalLetterStatus);
        letter.setLastUpdateBy(UserUtils.getUserId());
        letter.setLastUpdateDate(new Date());
        fmsReceiveCreditLetterService.save(letter);
    }
    logger.info("revokePresentAndAccount end, registerId={}", registerId);
    // AI_GENERATE_END [revokePresentAndAccount]
}
```

### 5.3 撤回 SQL 速查（手工执行 / DBA 介入时用）

> ⚠️ 手工执行 SQL 必须**按顺序**逐条执行，且整体包裹在一个事务里。下面以示例 ID 为例，实际请替换。

```sql
-- ============ 步骤A：撤销到账登记 ============
-- A1. 查询到账子表 ID（用于后续释放流水）
SELECT id FROM FMS_RCL_PRESENT_REGISTER_CHILD
 WHERE register_id = 'fa40522b-7a5e-4474-b2ca-3ed852e0caa2' AND data_type = '1'
   AND enabled_flag = '0';

-- A2 + A3. 释放流水关联与流水标签（假设上一步查到的 child_id 列表为 :childIds）
UPDATE FMS_REGISTER_TRANS_ASSOCIA
   SET enabled_flag = '1', validity_flag = '1',
       last_update_date = SYSDATE, last_update_by = '撤回操作人'
 WHERE child_id IN (:childIds);

UPDATE FMS_TRANSACTION_DETAILS_LABLE
   SET enabled_flag = '1', validity_flag = '1',
       last_update_date = SYSDATE, last_update_by = '撤回操作人'
 WHERE bus_details_id IN (:childIds);

-- A1. 逻辑删除到账子表
UPDATE FMS_RCL_PRESENT_REGISTER_CHILD
   SET enabled_flag = '1', validity_flag = '1',
       last_update_date = SYSDATE, last_update_by = '撤回操作人'
 WHERE register_id = 'fa40522b-7a5e-4474-b2ca-3ed852e0caa2'
   AND data_type = '1';

-- A4. 回写交单主表（状态 3→6，清空到账字段，beOver 置空）
UPDATE FMS_RCL_PRESENT_REGISTER
   SET status = '6',
       be_over = NULL,
       receive_account = NULL,
       receive_mode    = NULL,
       receive_type    = NULL,
       receive_date    = NULL,
       receive_amount  = NULL,
       account_fee     = NULL,
       operator        = NULL,
       operator_date   = NULL,
       account_remark  = NULL,
       last_update_by  = '撤回操作人',
       last_update_date = SYSDATE
 WHERE id = 'fa40522b-7a5e-4474-b2ca-3ed852e0caa2';

-- A6. 主信用证状态回退（仅在当前是 3 时才回退）
UPDATE FMS_RECEIVE_CREDIT_LETTER
   SET status = '6',
       last_update_by  = '撤回操作人',
       last_update_date = SYSDATE
 WHERE id = '55aa5f53-0c35-4a90-a272-cd8eef2ece02'
   AND status = '3';

-- ============ 步骤B：撤销交单登记 ============
-- B1. 删除交单附件
UPDATE FMS_ATTACHMENT
   SET enabled_flag = '1', validity_flag = '1',
       last_update_date = SYSDATE, last_update_by = '撤回操作人'
 WHERE bus_id = 'fa40522b-7a5e-4474-b2ca-3ed852e0caa2'
   AND bus_type = 'RCL_PRESENT';

UPDATE FMS_RCL_PRESENT_REGISTER
   SET enabled_flag = '1', validity_flag = '1',
       last_update_by  = '撤回操作人',
       last_update_date = SYSDATE

-- 先校验该证下是否还有其他有效交单
SELECT COUNT(1) FROM FMS_RCL_PRESENT_REGISTER
 WHERE rcl_id = '55aa5f53-0c35-4a90-a272-cd8eef2ece02'
   AND enabled_flag = '0';
-- 若上面查询为 0，则把主信用证状态回退到原始状态（这里假设原始状态是 4 新开）
UPDATE FMS_RECEIVE_CREDIT_LETTER
   SET status = '4',  -- 原始状态，按实际填写
```

## 六、关键风险点与防御性说明

1. **状态回退不是简单的"逆运算"**
   第一步 `save` 时代码**强制**把主表状态写成 `6`，但**没记录原状态**。撤回时若想恢复到 `4`（新开）或 `2`（签收），需要：
   - 由调用方传入 `originalLetterStatus`（推荐，从操作日志/快照里取）；
   - 或根据业务规则推断（如该证下已无任何交单 → 回到 `4`）。

2. **多交单场景**
   `setLetterStatus` 推进到 `3` 的条件是"所有交单金额累加 = 开证金额 且全部到账"。如果该信用证下**还有别的交单**已经到账，撤回本次交单时**不能**简单把主表状态从 `3` 回退到 `6`，需重新计算。撤回代码用 `findByParentId` 判断剩余交单已规避此风险。

3. **附件不可恢复**
   `updateAttachment` 是"先删后增"。本次到账附件为空，撤回时无需处理；但若用户原本上传过到账附件，撤回后这些附件**已经被逻辑删除**（`enabled_flag=1`），需要从备份或审计日志恢复。

4. **流水占用释放**
   本次 `registerList=[]` 未关联流水，A2/A3 实际是空操作；但如果有关联流水，必须**先释放关联和标签再删子表**，否则会留下孤儿数据，导致流水被永久占用（再次到账登记时报 `fms.transAssociaNo.already.associated`）。

5. **并发控制**
   建议在撤回方法里复用 `FmsConstants.REDIS_RECEIVE_REGISTER_KEY + registerId` 加分布式锁（与 `addAccount` 同一把锁），避免与正常到账登记并发冲突。

6. **审计与日志**
   撤回属于"反向操作"，强烈建议加 `@SysLog(value="撤回", desc="应收信用证交单/到账登记撤回")`，并在方法入口打 INFO 日志、异常打 WARN 日志（符合《阿里巴巴Java手册》日志规范）。

7. **数据完整性自检**
   撤回完成后建议返回结构化的核对清单（DTO），让前端二次确认：
   - 交单主表 status / be_over 是否已回退；
   - 主信用证 status 是否符合预期；
   - 子表/流水/标签是否全部释放；
   - 附件是否需要人工补传。

## 七、TL;DR

| 步骤 | 操作 | 写入表 | 字段关键变化 |
|---|---|---|---|
| **第 1 步 交单登记** | POST `/fmsrclpresentregister` | `FMS_RCL_PRESENT_REGISTER` (INSERT) | status=6 出库 |
| | | `FMS_RECEIVE_CREDIT_LETTER` (UPDATE) | status → 6 |
| | | `FMS_ATTACHMENT` (INSERT, busType=RCL_PRESENT) | 附件 |
| **第 2 步 到账登记** | PUT `/fmsrclpresentregister/fmsrclaccountregister` | `FMS_RCL_PRESENT_REGISTER_CHILD` (INSERT/DELETE) | 到账明细 |
| | | `FMS_REGISTER_TRANS_ASSOCIA` (INSERT) | 流水关联 |
| | | `FMS_TRANSACTION_DETAILS_LABLE` (INSERT) | 流水标签 |
| | | `FMS_RCL_PRESENT_REGISTER` (UPDATE) | status=3 到账, be_over=0 |
| | | `FMS_ATTACHMENT` (DELETE+INSERT, busType=RCL_ACCOUNT) | 到账附件 |
| | | `FMS_RECEIVE_CREDIT_LETTER` (UPDATE) | status → 3 |
| **撤回 第 2 步** | 释放流水标签 → 释放流水关联 → 逻辑删子表 → 回写交单主表（status=6, be_over=null, 到账字段置空）→ 主信用证状态 3→6 |
