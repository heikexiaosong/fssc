# 支付状态同步与查询 — 功能说明

本文档说明：**共享中心定时查询资金付款结果 → 接口平台回调 OP → 更新支付指令及单据支付状态 → 异步生成/导入凭证** 的完整链路，便于排查「指令已付款、单据状态未更新」类问题。

---

## 1. 整体链路概览

```
┌─────────────────────────────────────────────────────────────────────────┐
│  共享 FSC 定时任务                                                        │
│  JobCenter#queryEfsPayStatus                                             │
│    → 查 OP 待同步指令（paymentStatus=20）                                  │
│    → 调 FMS 查询付款申请单终态                                            │
│    → 组装 OpEfsPaymentDTO 列表                                            │
│    → POST opipboe/receivePayResult                                       │
└───────────────────────────────┬─────────────────────────────────────────┘
                                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  OP 接收支付结果                                                          │
│  OpIpBoeController#receivePayResult（批量）                               │
│    → receiveOnePayResult（逐条校验 + 内存赋值）                            │
│    → updateDetail / handleUpdateDetail（落库 + 联动）                     │
│      ├─ OP_EFS_PAYMENT 批量更新                                          │
│      ├─ changePaymentStatus → OP_PREPAY_PAYMENT / ZFS_BOE_PAYMENTS /     │
│      │                        ZFS_BOE_HEADER                             │
│      ├─ MQ → 报账(BOE)、台账、共享(FSC) 等                                │
│      └─ MQ PUSH_BOE_PAYMENT_SUCCESS_TO_OP → 凭证生成/导入                 │
└─────────────────────────────────────────────────────────────────────────┘
```

**单条 SAAS 接口**（与批量逻辑等价，不走批量预加载）：

- 入口：`POST opipboe/receiveOnePayResult`
- 实现：`OpIpBoeService#receiveOnePayResultBefore` → `receiveOnePayResult(OpEfsPaymentDTO)`

## 2. 共享侧：定时查询资金付款终态（FSC）

**入口类**：`cn.ztessc.job.JobCenter#queryEfsPayStatus`

### 2.1 查询 OP 待同步指令

| 项目 | 说明 |
|------|------|
| 接口 | `POST opefspayment/listEfsVByParams` |
| 典型条件 | `paymentStatus = 20`（付款中）、`batchAgencyPaymentNoIsNull = 0`（仅查代发批号为空的指令） |

```json
{
  "groupId": "<groupId>",
  "paymentStatus": "20",
  "batchAgencyPaymentNoIsNull": "0"
}
```

### 2.2 调用资金系统查询结果

| 项目 | 说明 |
|------|------|
| 接口 | `POST apiController/queryPaymentStatusByMore` |
| 入参 | 待查指令 ID 列表 `[opEfsPaymentDto.id, ...]` |

### 2.3 查询支付方式（汇率/属性映射）

| 项目 | 说明 |
|------|------|
| 接口 | `POST paymentmode/listByBody` |

按返回结果中的 `paymentModeCode` 批量匹配 `SysPaymentModeDTO`，用于后续状态、属性转换。

### 2.4 组装回调 DTO

资金返回 JSON 与 OP 指令匹配后，主要赋值：

| 字段 | 来源 |
|------|------|
| `paymentStatus` | FMS 状态经 `FmsInternalEnum.PAY_STATUS_WAY` 映射为 OP 状态码 |
| `paymentDate` / `lastUpdateDate` | `transactionTime`（交易时间） |
| 其他 | 银行流水、失败原因等（按接口返回补充） |

### 2.5 回调 OP

| 项目 | 说明 |
|------|------|
| 接口 | `POST opipboe/receivePayResult` |
| 入参 | `List<OpEfsPaymentDTO>` |
| 日志 | `INTERFACE_LOG`（`method = OpIpBoeController.receivePayResult`） |

## 3. OP 侧：接收支付结果（批量）

**入口**：`OpIpBoeController#receivePayResult`  
**实现**：`OpIpBoeService#receivePayResult`

### 3.1 批量预加载（减少 N+1 查询）

| 数据 | 来源 |
|------|------|
| `idEntityMap` | `OP_EFS_PAYMENT` 按 `id` |
| `paymentNoEntityMap` | `OP_EFS_PAYMENT` 按 `paymentNo` |
| `companyBankDTOMap` | 基础数据 `companybank/findListByParams`（按付款账号） |
| `cacheDtoMap` | 联行号缓存 |

### 3.2 分两路处理

| 分支 | 条件 | 处理方式 |
|------|------|----------|
| 普通指令 | `batchAgencyPaymentNo` 为空 | 逐条 `receiveOnePayResult(...)`，汇总后 **一次** `updateDetail` |
| 代发批号 | `batchAgencyPaymentNo` 非空 | `receiveOnePayResultForBatchAgencyPaymentNo`，走 `updateDetailForBatchAgencyPaymentNo` |

### 3.3 操作日志

- 批量场景：循环结束后 `saveLogByEfsPayList` → MongoDB **`OP_EFS_PAY_OPER_LOG`**
- 每条接口调用：`INTERFACE_LOG`

## 4. 单条处理：`receiveOnePayResult`

**核心类**：`OpIpBoeService#receiveOnePayResult`

### 4.1 定位支付指令

1. 优先按 `id` 查 `OP_EFS_PAYMENT`
2. 查不到则按 `paymentNo + groupId` 兜底

### 4.2 校验（决定是否继续更新）

| 校验项 | 不满足时的行为 |
|--------|----------------|
| 指令不存在 | 记录错误，`code=0`（单条接口）或 `code=1` 带 msg（批量接口） |
| DB 状态已是 **30（已付款）** | **拒绝更新**（终态保护），不再改库 |
| `payerBankAccountNum` 在基础数据不存在 | 记录 warn 写入 `errorMsg`，**不阻断**更新 |

> 注意：原草稿中 `if (one == null && one.getStatus() == 30)` 为笔误，实际代码为 **先判 null，再判 DB 状态是否为 30**。

### 4.3 写入 `OP_EFS_PAYMENT` 的字段（内存阶段）

**始终更新**（通过校验且非终态时）：

| 列名 | 入参字段 | 说明 |
|------|----------|------|
| `PAYMENT_STATUS` | `paymentStatus` | 直接覆盖 |
| `PREDICT_DATE` | `predictDate` | 非空才写 |
| `BANK_FLOW_NUMBER` | `bankFlowNumber` | 银行流水号 |
| `ERROR_MSG` | `errorMsg` + 校验信息 | 超长截断 |
| `PAYMENT_DATE` | `paymentDate` | 付款时间 |
| `LAST_UPDATE_DATE` | `paymentDate` 或当前时间 | |
| `BUSINESS_NUM` | `businessNum` | 业务流水号 |
| `REMARK` / `BILL_NUMBER` / `POSTAL_ORDER_CODES` / `RETURN_NUMBER` | 同名入参 | |
| `MODIFY_FLAG` | `modifyFlag` | 异常支付修改标识 |
| `PUSH_COUNT` | `pushCount` | 入参为空保留 DB 原值 |

**付款方**（`payerBankAccountNum` 非空且公司银行账户存在时，以基础数据为准）：

`PAYMENT_ACCOUNT_ID`、`PAYER_BANK_ACCOUNT_NUM/NAME`、`PAYER_BANK_BRANCH_NAME`、`PAYER_BANK_UNITED_CODE`、`PAYER_BANK_HEAD_NAME/CODE`

**支付成功（`paymentStatus = 30`）额外更新**：

`GATHER_BANK_*` 收款方信息、`SITES_TYPE`、`PAYMENT_MEMO`；若付款账号为空则从入参直接写付款方字段。

> 入参 JSON 中的 `boeNo`、`applyAmount`、`leId` 等大量字段**不会**从入参直接覆盖，而是保留 DB 原值，仅上述字段被显式修改后再整体落库。

### 4.4 异常支付分支

当 `frontSource = ERROR_PAY` 时额外写入：

- `OP_EFS_PAYMENT_ERROR_LOG`
- `OP_EFS_PAYMENT_ATTACHMENT`（`zfsAttachmentDtos`）

## 5. 落库与联动：`updateDetail` → `handleUpdateDetail`

**入口**：`OpEfsPaymentService#updateDetail`  
**核心**：`handleUpdateDetail`

### 5.1 更新 `OP_EFS_PAYMENT`

1. 按 id 批量查 DB 当前记录
2. `EntityUtils.copyPageToDb(DTO, entity)` 全量拷贝
3. 补充：`ACTUAL_PAYMENT_CURRENCY`（空则取 `CURRENCY_CODE`）、`PAYMENT_MODE_CODE`（非空则覆盖）
4. `updateBatch(entityList)` 批量保存

### 5.2 组装 MQ 映射 `mqMap`

结构：`Map<key, Map<paymentId, OpEfsPaymentDTO>>`

| `enableCashierAuditFlag` | 外层 key | 内层 key |
|--------------------------|----------|----------|
| `Y`（出纳审核） | `"Y"` | 预支付指令 id（`paymentId`，即 `OP_PREPAY_PAYMENT.id`） |
| 非 `Y` | `boeHeaderId` | 单据付款行 id（`ZFS_BOE_PAYMENTS.id`） |

当 `paymentStatus = 30` 时，同步写入 `successPayBoeMap`，供后续凭证 MQ 使用。

### 5.3 `changePaymentStatus` — 更新单据支付状态

**调用链**：`OpBoeBaseService#changePaymentStatus` → `AbstractBoeBaseCoreServiceImpl#changePaymentStatus`

#### 第一步：出纳审核路径 — 更新 `OP_PREPAY_PAYMENT`

条件：`mqMap` 中存在 key `"Y"`。

| 列名 | 赋值 |
|------|------|
| `PAYMENT_STATUS` | 来自 `OpEfsPaymentDTO.paymentStatus` |
| `LAST_UPDATE_DATE` | 当前时间 |

并按 **拆分/合并/普通** 三种情况，将 `"Y"` 下的数据 **重映射** 为：

```
Map<boeHeaderId, Map<ZFS_BOE_PAYMENTS.id, OpEfsPaymentDTO>>
```

合并进 `mqMap`，供第二步使用。

#### 第二步：更新 `ZFS_BOE_PAYMENTS`（单据付款行）

遍历每个 `boeId`（排除 `"Y"`），对该单据下所有付款行：

| 列名 | 赋值逻辑 |
|------|----------|
| `PAYMENT_STATUS` | 来自匹配到的 `OpEfsPaymentDTO`；异常/付款中等状态会做归一（如 11/21/22 → 22，16/20 → 20） |
| `ACTUAL_PAYMENT_AMOUNT` | 支付成功(30)/作废(40)/拆分时汇总实付金额；出纳审核路径可能取预支付行金额 |
| `LAST_UPDATE_DATE` | 当前时间 |

持久化：`zfsBoePaymentsService.updateBatch`

#### 第三步：更新 `ZFS_BOE_HEADER`（单据头）

按该单据**所有付款行**状态集合聚合（优先级：付款异常 > 作废 > 失败 > 退票 > … > 已付款 > 无需付款）：

| 列名 | 赋值逻辑 |
|------|----------|
| `PAYMENT_STATUS` | 聚合后的单据级支付状态 |
| `LAST_UPDATE_DATE` | 当前时间 |
| `PAYMENT_FAILURE_INFO` | 各行失败原因拼接 |
| `PAYMENT_AMOUNT` | 各行 `paymentAmount` 之和 |
| `PAYMENT_NO` | 支付指令编码拼接 |
| `FS_APPROVAL_TIME` | 首条非空复审时间 |
| `EFS_PAYEE` / `EFS_PAYMENT_ACCOUNT` / `EFS_PAYMENT_STATUS` / `EFS_PAYMENT_AMOUNT` | 通知用拼接字段 |
| `EFS_PAYMENT_ACCOUNT_NAME` / `EFS_PAYMENT_UNITED_CODE` / `PAYER_BANK_HEAD_CODE` / `OUT_SETTLE_NO` | 付款账户相关信息 |
| `EFS_MAX_PAYMENT_DATE` | 各行 `paymentDate` 最大值 |

持久化：`zfsBoeHeaderService.updateBatch`

单据头 **`PAYMENT_DATE`** 不在本方法内直接更新；当聚合状态为 30 时，通过 MQ `UPDATE_BOE_PAYMENT_DATE` / `UPDATE_OP_PAYMENT_DATE` 异步回写。

#### 后续联动（`OpBoeBaseService` 内）

- 规则引擎：`doExecuteBoePayStatusChangeAfterRule`
- MQ → 共享：`OP_PAYMENT_STATUS_TO_FSC`
- 支付结果通知：`sendPaymentResultNotifyForMap`

### 5.4 其他 MQ（同一 batchNo）

| MQ 枚举 | 用途 |
|---------|------|
| `OP_PAYMENT_STATUS_TO_BOE` | 通知报账模块同步付款信息 |
| `OP_PAYMENT_SUCCESS_TO_LDG` | 台账/票据 |
| `NOTICE_OP_PAYMENT_TO_LDG_ASSET` | 租赁资产（支付成功列表） |
| 付款时效 | `countPaymentAge` → BI |

### 5.5 凭证 MQ：`PUSH_BOE_PAYMENT_SUCCESS_TO_OP`

**触发**：`handleUpdateDetail` 完成后，`pushBoePaymentSuccessToOp(successPayBoeMap)`

| 项目 | 值 |
|------|-----|
| MQ 枚举 | `DataPush2Op.PUSH_BOE_PAYMENT_SUCCESS_TO_OP` |
| 消费 URL | `opefspayment/compensate/boePaymentSuccess` |
| 实现方法 | `OpEfsPaymentService#boePaymentSuccess` |

消费端按 `boePaymentStatusIdentifier` 排序，保证「最后一笔支付指令」排在末尾（影响实付凭证状态是否变为 15）。

## 6. 凭证生成与导入逻辑

**入口**：`OpEfsPaymentService#boePaymentSuccess`

```
boePaymentSuccess
  ├─ genVoucherWhenPaySuccess      // 生成付款/退票凭证
  └─ importVoucherWhenPaySuccess   // 更新已有凭证状态并导入
```

### 6.1 生成凭证 `genVoucherWhenPaySuccess`

| 出纳审核 | 分支方法 |
|----------|----------|
| `enableCashierAuditFlag = Y` | `geneVoucherForEnableCashierAudit`（预支付 id → 查 `OP_PREPAY_PAYMENT` → 关联单据） |
| 非 Y | `geneVoucherForDisableCashierAudit`（`boePaymentId` → 查 `ZFS_BOE_PAYMENTS`） |

按单据类型凭证配置（`createNode = PAY_SUCCESS`）：

- **新建**：`geneVoucherAndImportByBoePayment` → `geneVoucherNew` → 写入 **`OP_VOUCHER_HEADERS` / `OP_VOUCHER_LINES`**
- **刷新已有**（初审已生成的实付/付款凭证）：`updateVoucherAndImportByBoePayment` 或 `refreshVoucherAndImportByBoePayment`

生成成功后：

- `OP_EFS_PAYMENT.VOUCHERNO_WHENPAYSUC` 记录凭证事务号
- MQ `OP_VOUCHER_TO_FSC` 同步共享

### 6.2 导入/改状态 `importVoucherWhenPaySuccess`

调用 `prepareImportVoucher`（plugin），按凭证类别处理：

| 凭证类别 | 状态变更条件 |
|----------|--------------|
| 实付凭证 | 单据头 `paymentStatus=30` **且** `boePaymentStatusIdentifier=1`（最后一笔） |
| 付款凭证 | 当前支付行付款成功即可 |

更新 **`OP_VOUCHER_HEADERS`**：

- `VOUCHER_STATUS` → 15（待同步）或 14（需凭证审核）
- `PAYMENT_DATE` / `LAST_UPDATE_DATE`

并通过 MQ `OP_VOUCHER_STATUS_TO_FSC` 通知共享。

## 7. 支付状态码速查

| 值 | 含义 |
|----|------|
| 0 | 无需付款 |
| 5 | 待出纳审核 |
| 6 | 未付款 |
| 10 | 待付款 |
| 12 | 支付退票 |
| 16 | 推送中 |
| 20 | 付款中 |
| 25 | 付款失败 |
| 30 | **已付款** |
| 40 | 支付作废 |
| 22 | 付款异常（含 11/21 等归并） |

**终态保护**：DB 中 `OP_EFS_PAYMENT.PAYMENT_STATUS = 30` 时，`receiveOnePayResult` 不再接受状态更新。

## 9. 排查 SQL（支付状态不一致）

### 9.1 单据 OP/BOE 支付状态不一致

```sql
-- 指令已 30，但 OP 头表或 BOE 头表未 30
SELECT h.id,
       h.BOE_NO,
       oep.PAYMENT_NO,
       oep.PAYMENT_DATE,
       oep.PAYMENT_STATUS   AS 指令支付状态,
       oep.CREATE_DATE      AS 指令创建时间,
       oep.LAST_UPDATE_DATE AS 指令最后更新,
       h.PAYMENT_STATUS     AS 支付状态_BOE,
       zbh.PAYMENT_STATUS   AS 支付状态_OP,
       h.LAST_UPDATE_DATE   AS boe最后更新,
       zbh.LAST_UPDATE_DATE AS op最后更新
  FROM zfs_op.zfs_boe_header zbh
  LEFT JOIN zfs_boe.zfs_boe_header h ON h.ID = zbh.ID
  LEFT JOIN zfs_op.op_efs_payment oep ON oep.BOE_HEADER_ID = zbh.ID
 WHERE zbh.ENABLED_FLAG = '0'
   AND h.ENABLED_FLAG = '0'
   AND h.PAYMENT_STATUS = '30'
   AND zbh.PAYMENT_STATUS <> '30'
   AND oep.LAST_UPDATE_DATE > '2026-05-26 00:00:00'
   AND oep.LAST_UPDATE_DATE < '2026-05-26 10:00:00'
 ORDER BY oep.LAST_UPDATE_DATE DESC, oep.CREATE_DATE DESC;
```

### 9.2 按接口日志反查同步记录

```sql
SELECT oep.PAYMENT_NO,
       oep.PAYMENT_DATE,
       oep.BOE_HEADER_ID,
       oep.CREATE_DATE      AS 指令创建时间,
       oep.LAST_UPDATE_DATE AS 指令最后更新,
       il.*
  FROM zfs_op.interface_log il
  LEFT JOIN zfs_op.op_efs_payment oep ON oep.PAYMENT_NO = il.BUSI_ID
 WHERE il.METHOD = 'cn.ztessc.controller.ip.OpIpBoeController.receivePayResult'
   AND il.create_date > '2026-05-26 09:35:00'
   AND il.create_date < '2026-05-26 09:36:00'
   AND oep.PAYMENT_DATE IS NOT NULL
   AND oep.PAYMENT_DATE < il.create_date;
```

### 9.3 排查建议

1. 查 `INTERFACE_LOG.RESPONSE_PARAM` 中 `code` 是否为成功；若 msg 含「状态为 30，不再接收」则为重复回调。
2. 查 `OP_EFS_PAY_OPER_LOG`（MongoDB）确认 `action=ReceiveStatus` 是否有记录。
3. 若 `OP_EFS_PAYMENT=30` 但 `ZFS_BOE_HEADER<>30`：重点看 `changePaymentStatus` 是否执行、`vendorId` 是否匹配导致跳过付款行更新。
4. 出纳审核单据（`ENABLE_CASHIER_AUDIT_FLAG=Y`）：确认 `OP_PREPAY_PAYMENT` 状态及 `mqMap` 重映射是否正确。
5. 凭证未导入：查 `PUSH_BOE_PAYMENT_SUCCESS_TO_OP` 消费是否成功，以及 `boePaymentStatusIdentifier` 是否影响实付凭证状态。
