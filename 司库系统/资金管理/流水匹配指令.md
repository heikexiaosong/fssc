### 交易明细匹配指令
cn.ztessc.service.task.JobCenter#synDetailMatchInstruction
```sql
-- 
select * from fms_account fav where 1=1

-- 当日待匹配数据
select * 
from FMS_TRANSACTION_DETAILS_DAY 
where ENABLED_FLAG = '0' 
  and ACCOUNT_ID = :accountId 
  and INSTRUCTION_NO is null 
  and TRANSACTION_TYPE = '0' 
  and INSTRUCTION_SOURCE is null 
  and BANK_NUMBER is not null
  and (INSTRUCTION_MATCH_TIME <= 50 or INSTRUCTION_MATCH_TIME is null ) 
order by INSTRUCTION_MATCH_TIME asc,CREATE_DATE desc

-- key: bankNumber^currencyCode^transactionAmount
-- batchConditionMap： <key, [<"conditionBeginDate", TransactionDate-DiffTIme>, <"conditionEndDate", TransactionDate+DiffTIme>]>


-- 
select i.* 
  from fms_payment_instructions i 
       left join FMS_BATCH_QUERY_CONDITION c on c.PAYER_BANK_ACCOUNT_NUM=i.PAYER_BANK_ACCOUNT_NUM and c.CURRENCY_CODE=i.PAYMENT_CURRENCY and c.CONDITION_AMOUNT=i.APPLY_AMOUNT
 where i.ENABLED_FLAG = '0' 
  and i.PAYMENT_STATUS = '30' 
  and i.INSTRUCTION_TYPE in ('1', '3')
  and c.CONDITION_TYPE = '002' -- 交易明细匹配指令 cn.ztessc.utils.FmsEnumType.conditionType#CONDITION_TYPE_002 
  and c.CONDITION_BATCH_NO = :conditionBatchNo
  and i.PAYMENT_DATE >= c.CONDITION_BEGIN_DATE 
  and i.PAYMENT_DATE <= c.CONDITION_END_DATE 

-- 更新流水数据
update fms_transaction_details_day 
set INSTRUCTION_NO = ? , INSTRUCTION_MATCH_TIME = ? , INSTRUCTION_SOURCE = ? , PAYMENT_FLOW_FLAG = ?
where id = ? and INSTRUCTION_NO is null

```


1. 流水自带指令编码直接匹配（optimizeWithInstructionNo）
- 流水 INSTRUCTION_NO 非空的记录
- 批量查指令表(MATCH_COUNT 为 null/0（未被其他流水占用）、有效；若系统参数"线下支付生成明细"=N，还要求转账指令（INSTRUCTION_TYPE='1'）且（支付状态 30成功/29部分成功 或 发送状态 3待查询/4查询中/5已发送）
- 校验：指令编码 + 本方账号 + 币种 + 金额，对方账号有值时也须一致（农行收方账号允许去掉前 2 位模糊比对）；指令不能已在 matchedNos 中
- ✅ 匹配上：INSTRUCTION_SOURCE=2 银行返回，立即更新 DB
- ❌ 匹配不上：把流水上的指令编码置空，放回未匹配池走后续轮次

2. 六要素精确匹配（matchDetailsInstruction）
- 按流水的本方账号+币种+金额, 指令支付日期须落在流水交易日期 ± 时间差内; 指令同样要求未被占用（MATCH_COUNT=null/0）; 转账指令须支付成功/部分成功或发送中（允许线下支付时另含线下指令状态=成功）
- 匹配 Key = 本方账号-对方账号-币种-金额（农行收方额外生成去前 2 位的 Key）
- 1. 流水已有 FMS_DETAILS_INSTRUCTION 关联记录且指令校验通过 → 直接取关联表中唯一未占用的指令编码; 2. Key 命中且唯一 → 直接匹配; 3. Key 命中且多个 → multicaseMatch 降级筛选：①交易用途+摘要都相等 → ②之一相等 → ③都不等取全部候选；每组内再选与交易时间时间差最小的指令
- Key 命中的记录（无论最终是否匹配成功）匹配次数 +1；Key 未命中的进入第 3 轮


3. 兜底模糊匹配（autoMatchUnmatchedDetails）
- 只针对 代发工资单 / 批量付款单（BOE_TYPE）类型的候选指令
- 匹配 Key = 本方账号-币种-金额-交易类型（不含对方账号），再按"交易日期 vs 指令支付日期天数差 ≤ 时间差阈值"过滤
- 唯一命中 → 匹配；多个命中 → 取时间差最小的；已有关联记录的直接沿用
- 仍未命中 → 保持未匹配状态


匹配上 → 更新哪些数据
  流水表（当日/历史）: 
    - INSTRUCTION_NO	匹配到的指令编码
    - INSTRUCTION_SOURCE	0:自动匹配（第2/3轮）;  2: 银行返回（第1轮）
    - PAYMENT_FLOW_FLAG	  1: 主动付款（batchProcessDayPaymentFlowFlag：有指令编码即置 1）
    - INSTRUCTION_MATCH_TIME	置 1（防止再次参与匹配）

  新增流水-指令关联表 FMS_DETAILS_INSTRUCTION 记录（第 2/3 轮匹配成功时插入）
  指令表 FMS_PAYMENT_INSTRUCTIONS：对应指令 MATCH_COUNT + 1（updateMatchCountByInstructionNos）→ 该指令后续不再作为候选，防止一笔指令匹配多条流水
  指令候选集为空时（本轮查不到任何候选指令）：所有流水只做 INSTRUCTION_MATCH_TIME + 1（null 视为 1），其余字段不动

没匹配上 → 怎么更新
  流水表
    - PAYMENT_FLOW_FLAG	0 被动扣款
    - INSTRUCTION_MATCH_TIME	置 1 —— 不再参与后续自动匹配（后续靠人工匹配）
    - INSTRUCTION_NO	保持为空（第 1 轮预匹配失败的会被显式置空）
    - INSTRUCTION_SOURCE	不设置（保持 NULL）

  被动扣款的延伸处理（processPassiveDeductionData，同时满足以下条件才执行）：
    - 本方账户维护的"是否归集账号"标识 = 0（是）
    - 系统参数 FUND_POOL_MODE = Y（银行资金池模式开启）
    - 当日表只处理交易日期 = 今天的；历史表全部
    - 账户配置了资金池加入时间 CAPITAL_POOL_JOIN_TIME，且交易日期 ≥ 该日期
  → 满足则生成内部户明细账（FMS_TRANSACTION_DETAILS_TNTERIOR，MAPPED_TYPE_005）：对方账号为空的直接生成；对方账号非空的需对方是账户组归集账号（资金池上划/下拨场景）。
