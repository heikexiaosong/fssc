## 1. 背景与定位

内部借款台账执行「放款」时，若计息方式为**周期性计息**（按月 / 按季 / 按半年 / 按年），后端需要计算两个落库字段：

| 落库字段 | 业务含义 | 存储形式示例 |
|---|---|---|
| `billingMonth` 结息周期 | 每年的哪几个月结息 | `"3,6,9,12"` |
| `billingDay` 结息日期 | 每个结息月的几号结息 | `"15"` |

这两个字段**不是简单透传入参**，而是由后端根据「计息方式 + 首次付息日期类型」推导的**基准日期**重新计算并覆盖，随后随放款主记录一起落库（表 `fms_inner_loan_ledger_record`）。

**调用时机**：`loanBusinessOpera` L1438 —— 位于 DTO→Entity 拷贝（L1442 `ConvertUtils.sourceToTarget`）**之前**，因此计算结果必然进入落库实体。

## 3. 核心规则

### 3.1 计息方式 → 是否计算、间隔月数

枚举来源：`FmsInnerLoanEnum.INTEREST_WAY`

| 计息方式 | 枚举值 | 是否触发计算 | 间隔月数 |
|---|:---:|:---:|:---:|
| 定期结息 | `1` | ❌ 不计算 | — |
| 利随本清 | `2` | ❌ 不计算 | — |
| 预扣利息 | `01` | ❌ 不计算 | — |
| 一次付清 | `02` | ❌ 不计算 | — |
| **按月** | `04` | ✅ | 1 |
| **按季** | `05` | ✅ | 3 |
| **按半年** | `06` | ✅ | 6 |
| **按年** | `07` | ✅ | 12 |
| 其他 | `08` | ❌ 不计算 | — |

### 3.2 首次付息日期类型 → 基准日期

| 类型值 | 业务含义 | 基准日期取自 | 举例（按季结息） |
|:---:|:---|:---|:---|
| `1` | 放款日对应日 | 本次放款的**放款日期** `dto.effectiveDate` | 放款日 2026-03-15 → 结息月 3,6,9,12；结息日 15 |
| `2` | 合同到期日 | 借款台账的**合同终止日期** `ledger.loanEndDate` | 合同到期 2026-12-20 → 结息月 3,6,9,12；结息日 20 |
| `3` | 自定义日期 | 用户手工填写的 `dto.firstInterestCustomDate` | 自定义 2026-01-10 → 结息月 1,4,7,10；结息日 10 |
| 空 / 其他值 | 未选择或非法 | **无基准日期，返回空** | 不计算结息周期，流程静默跳过 |

> 自然语言描述：先看用户有没有选「首次付息日期类型」——没选就到此为止；选了就按类型三选一取日期（放款日期 / 台账合同到期日 / 自定义日期）；类型非法视同没选。

## 4. 算法详解

### 4.1 结息周期 billingMonth 的生成算法

**第一步：取基准月**

```
startMonth = DateUtil.month(baseDate) + 1
```

⚠️ hutool 的 `DateUtil.month()` 返回 **0 基月份**（1 月 = 0），`+1` 转为日常 1~12 的自然月。这是本段代码最易误读的一行。

**第二步：筛选月份**

遍历 `month = 1..12`，满足下式的月份入选：

```
(month - startMonth + 12) % 间隔月数 == 0
```

- `+12`：保证被除数非负（`month - startMonth` 最小为 −11，加 12 后 ≥ 1），规避 Java 负数取模产生负值的问题；
- `% 间隔 == 0`：该月与基准月恰好相差整数个周期；
- 因 `month` 从 1 递增，输出为**自然年升序**（不是从基准月起排）。

**示例推演**

| 基准月 | 间隔 | 判定式 | 结果 |
|:---:|:---:|:---|:---|
| 2 | 3（按季） | `(m-2+12)%3==0` → m=2,5,8,11 | `"2,5,8,11"` |
| 12 | 3（按季） | `(m-12+12)%3==0` → m%3==0 → 3,6,9,12 | `"3,6,9,12"` |
| 1 | 6（按半年） | `(m+11)%6==0` → m=1,7 | `"1,7"` |
| 任意 s | 1（按月） | 恒成立 | `"1,2,3,...,12"` |
| 11 | 12（按年） | `(m-11+12)%12==0` → m=11 | `"11"` |

### 4.2 结息日期 billingDay 的生成

```
billingDay = baseDate 的“日”部分（1~31，转字符串）
```

⚠️ **不做月末钳制**：基准日为 31 日时，小月（2/4/6/9/11 月）是否按 30 日或月末处理，由下游结息逻辑（消费 `billingMonth/billingDay` 的 `getPerEffectiveDate` 系列方法）决定，此处原样存 31。

### 5.2 getBaseDate（L1575-1593）


本方法只做一件事：**根据用户选择的「首次付息日期类型」，决定锚点日期（baseDate）从哪里取。**

2. 选了，就按类型三选一取日期：放款日期 / 台账合同终止日期 / 用户自填日期；
3. 类型是别的值（理论上不该出现）→ 同没选一样，返回空。

## 7. 行为特征与注意事项

| # | 特征 | 说明 | 潜在影响 |
|:---:|:---|:---|:---|
| 1 | **静默跳过，不报错** | 计息方式为空/非周期性、类型为空/非法、自定义日期为空，均直接 return，无异常无提示 | `firstInterestDateType` 漏传时放款照常成功，若下游结息依赖这两个字段，问题会延后暴露 |
| 2 | **不清空旧值** | 只有“算得出来”的分支才覆盖 `billingMonth/billingDay`；算不出来时入参原值直接落库 | 后端没有兜底计算，数据正确性取决于调用方是否传对值 |
| 3 | **无月末钳制** | 基准日 31 日时 `billingDay="31"` 原样入库 | 2/4/6/9/11 月的实际结息日由下游结息逻辑解释（30 日或月末），需与下游口径核对 |
| 4 | **升序自然月输出** | 输出按 1→12 排序，不按“从基准月起”排序 | 例 2：基准 12 月按季得到 `3,6,9,12` 而非 `12,3,6,9`，阅读数据时注意 |
| 5 | **与编辑放款联动** | `rateRelatedFieldsChanged`（L1293）将 `billingMonth`、`billingDay` 列入计息信息变更比对字段 | 编辑放款时改动结息周期/日期，会触发利率调整记录重建（`dealInitRecordByInnerId`） |
| 6 | **类型值硬编码** | `switch` 只认 `"1"/"2"/"3"` | 前端字典若新增类型，此处不会自动兼容，落入 default 静默不计算 |

## 9. 计息记录表 FMS_INNER_LOAN_INTEREST_RECORD 生成逻辑

放款流程除了写放款主表，还会向计息记录表（内部借款计息分段）**重建式写入**数据——"先删后插"，且删除范围限定在本笔放款名下。

### 9.1 触发点（loanBusinessOpera 内）

`FmsInnerLoanLedgerRecordService.java:1492-1494`：

```java
// 是否计息开启后：(重新计算利息记录)
if (FmsInnerLoanEnum.IS_INTEREST.TRUE.getValue().equals(entity.getIsInterest())) {
    saveInterestRecord(one, baseDataTranslateUtils.baseDataTranslate(entity, FmsInnerLoanLedgerRecordDTO.class));
}
```

注意：把已落库的 entity 再转回 DTO 传入，所以入参自带主键 id。

### 9.2 数据创建链路

```

   │  条件① 放款记录 isInterest = '1'（计息）
   ▼

   │  条件② 放款 amount 非空
```

按 `effectiveDateNum`（生效日）分组，**每个日期段生成一条计息分段记录**：

### 9.4 三条"不生成"规则

| 规则 | 行号 | 效果 |
|---|:---:|---|
| `rate == 0`（该段无有效利率） | :5064 | 该段跳过，不插记录 |
| `unrepayAmount == 0`（该段时点已还清） | :5059/5064 | 该段跳过，且后续不再封口 |
| 还款记录 `repaymentPrincipal <= 0` | :4984-4987 | 不参与 loanAmount 累计（部分还息记录单独走 `partialRepayList`，:4973-4976） |

### 9.5 补充说明

1. **重建范围**是"本笔放款记录ID"维度（`deleteByLoanIdAndLedgerId`），不是整个台账——多次放款各自维护自己的计息分段，互不覆盖。
2. 放款流程走的是**双参 `saveInterestRecord`（L4919）**。类里还有两个同族方法也写这张表，但**不在放款链路上**：单参版（L1995，按 loanId 全删全建，借款编辑用）和 `saveInterestRecordList`（L1963，批量场景用）——查数据来源时注意区分入口。
3. 本表是**派生表**——字段值全部由放款记录 + 利率调整记录 + 还款记录 + 展期记录推算，不直接存前端入参；其中利率调整记录正是放款时 `saveAdjustRecord`（L1690）写入的两条初始记录，结息周期字段（`billingMonth`/`billingDay`，见第 3、4 章）则由下游结息逻辑在消费本表分段时使用。

```java
 * 根据计息方式计算结息周期和结息日期.
 * 计息方式为04(按月)/05(按季)/06(按半年)/07(按年)时，计算billingMonth和billingDay。

private void calculateBillingCycle(FmsInnerLoanLedgerRecordDTO dto, FmsInnerLoanLedgerDTO ledger) {
    String interestWay = dto.getInterestWay();
    if (StrUtil.isBlank(interestWay)) {
        return;
    }
    // 根据计息方式确定结息间隔月数
    Integer billingMonthValue = null;
    if (StrUtil.equals(interestWay, FmsInnerLoanEnum.INTEREST_WAY.MONTHLY.getValue())) {
        billingMonthValue = 1;
    } else if (StrUtil.equals(interestWay, FmsInnerLoanEnum.INTEREST_WAY.QUARTERLY.getValue())) {
        billingMonthValue = 3;
    } else if (StrUtil.equals(interestWay, FmsInnerLoanEnum.INTEREST_WAY.SEMI_ANNUAL.getValue())) {
        billingMonthValue = 6;
    } else if (StrUtil.equals(interestWay, FmsInnerLoanEnum.INTEREST_WAY.ANNUAL.getValue())) {
        billingMonthValue = 12;
    }
    if (billingMonthValue == null) {
        return;
    }
    // 根据首次付息日期类型确定基准日期
    Date baseDate = getBaseDate(dto, ledger);
    if (baseDate == null) {
        return;
    }
    // 以基准日期所在月为起点，按间隔生成结息月份序列（升序输出）
    // 例：基准月=2，按季(间隔3) → "2,5,8,11"
    int startMonth = DateUtil.month(baseDate) + 1;
    StringBuilder sb = new StringBuilder();
    for (int month = 1; month <= 12; month++) {
        if ((month - startMonth + 12) % billingMonthValue == 0) {
            if (sb.length() > 0) {
                sb.append(",");
            }
            sb.append(month);
        }
    }
    dto.setBillingMonth(sb.toString());
    // 设置结息日期（基准日期的日部分）
    int day = DateUtil.dayOfMonth(baseDate);
    dto.setBillingDay(String.valueOf(day));
}

/**
 * 根据首次付息日期类型获取基准日期.
 *
 * @param dto 放款记录DTO
 * @param ledger 内部借款台账DTO
 * @return 基准日期
 */
private Date getBaseDate(FmsInnerLoanLedgerRecordDTO dto, FmsInnerLoanLedgerDTO ledger) {
    String firstInterestDateType = dto.getFirstInterestDateType();
    if (StrUtil.isBlank(firstInterestDateType)) {
        return null;
    }
    switch (firstInterestDateType) {
        // 放款日对应日 → 放款日期（effectiveDate）
        case "1":
            return dto.getEffectiveDate();
        // 合同到期日 → 内部借款台账终止日期
        case "2":
            return ledger.getLoanEndDate();
        // 自定义日期 → firstInterestCustomDate
        case "3":
            return dto.getFirstInterestCustomDate();
        default:
            return null;
    }
}
```
