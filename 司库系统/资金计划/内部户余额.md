3. 获取日期内内部户余额积数最大日期记录
```sql
-- 获取日期内内部户余额积数最大日期记录
select t.*
  from fms_inner_balance  t
       right join ( select ACCOUNT_ID,max(REGISTER_DATE) as REGISTER_DATE
                     from fms_inner_balance fib
                     where fib.ACCOUNT_ID = :innerId
                       and fib.REGISTER_DATE < :registerDate
                       and fib.enabled_flag = '0'
                    group by fib.ACCOUNT_ID ) tmp on t.ACCOUNT_ID=tmp.ACCOUNT_ID and t.REGISTER_DATE= tmp.REGISTER_DATE
 where t.ACCOUNT_ID = :innerId
   and t.enabled_flag = '0'
```

4. 判断 flag
flag = true;
// 传入的日期小于等于计息起始日 flag = true; 

// 否则： flag = (ObjUtil.isEmpty(initAmount) || ObjUtil.isEmpty(initAmount.getStartAmount())
                    || initAmount.getStartAmount().compareTo(BigDecimal.ZERO) == 0) && ObjUtil.isNotEmpty(
                    accountEntity.getBeginBalance());
                    
                    当时间已经过了计息起始日，flag 是否为 true 取决于两个大条件必须同时满足（&& 关系）：                    
                      条件 A（满足其一即可）：起算金额为空或为 0                    
                        ObjUtil.isEmpty(initAmount)：没有传入初始化金额对象。                    
                        ObjUtil.isEmpty(initAmount.getStartAmount())：传入了对象，但里面的具体金额 startAmount 是空的。                    
                        initAmount.getStartAmount().compareTo(BigDecimal.ZERO) == 0：传入了金额，但金额恰好等于 0。                    
                      条件 B：账户本身存在期初余额                    
                        ObjUtil.isNotEmpty(accountEntity.getBeginBalance())：数据库或实体中，该账户的 beginBalance（期初余额）不是空的                    
                      结果：只有当“外部没有给有效的起算金额（为空或0）”，同时“账户自身带有期初余额”时，flag 才为 true。

 总结该段代码的业务意图这个 flag 标签大概率代表 “是否应该读取系统配置的期初余额”。
  新开户/计息期初（时间 $\le$ 计息起始日）：无条件信任期初，flag = true。
  日常计算/中途计算（时间 $>$ 计息起始日）：如果外部没传有效的动态起算金额（为空或0），但系统里有这笔钱的底账（期初余额不为空），则兜底使用期初余额，flag = true；否则为 false（可能走别的流水累加逻辑）。
